# Независимая проверка CHECK-RECHECK2-5eba5135

2026-09-24. Проверяемый документ: [CHECK-RECHECK2-5eba5135.md](CHECK-RECHECK2-5eba5135.md).

## Граница проверки

Проверено текущее незакоммиченное дерево `master` при `HEAD=7c4d1804`. До создания этого файла было 57 изменённых отслеживаемых файлов и четыре новых файла; `origin/master=1fa8defc` — только локальная ссылка на удалённую ветку. Дайджест дерева кода при `LC_ALL=C bash tasks/matrix.sh digest`: `6955da1061b3abb80d9c8f7706e60f58fdccfad45bbef0edcf41bc8036a7fbd5`. Код и тесты не редактировались. Пробы ниже использовали локальный PHP 8.5.4, уже установленный образ `ivanshift/rutorrent:latest` без сети и синтетические ответы; живые трекеры, FPM/nginx, запущенный rTorrent и развёрнутая версия не проверялись. Полная PHP-матрица и исторические мутационные прогоны отчёта повторно не запускались. Этот новый файл находится под игнорируемым Git каталогом `tasks/` и в индекс не добавлен.

**Главный вывод.** Отказы `system.multicall` и `f.multicall`, равно как пропущенная проверка Tapochek CP1251 в образе без `iconv`, реальны. Однако отчёт местами превращает доказанное свойство кода в недоказанное утверждение о живом сервисе, а некоторые предложенные исправления меняют контракт или ослабляют границу доверия. Ниже каждому из 46 пунктов дан отдельный вердикт; «условно» означает, что механизм есть, а заявленное последствие не доказано.

## Существенные поправки к выводам и советам отчёта

1. Фраза «существует на проде сейчас» в шапке не следует из проверки `HEAD`: локальный `master` на три коммита впереди `origin/master`, а исправления лежат в рабочем дереве. На `origin/master=1fa8defc` отказы P1 и P2 воспроизводятся, но это устанавливает состояние локальной Git-ссылки, а не развёрнутого сервиса. Там обычный сырой `d.multicall2` также отвергается даже без Ratio: нынешнего списка `$safeGetters` в той версии нет. Нужны версия и политика живой двери, прежде чем утверждать её состояние.
2. Для P1 нельзя просто рекурсивно вызвать `XMLRPCProxy::decide()` для членов `system.multicall` и затем отправить внешний вызов как доверенный. Неизвестный одиночный метод может вернуть `send, trusted=false` ([xmlrpc_proxy.php](../../php/xmlrpc_proxy.php)); повышение всего составного запроса до `trusted=true` обойдёт политику. Требуется правило для доверия *всех* членов.
3. Для P2 отчёт предлагает добавить `f.create_queued.set` и `f.resize_queued.set`. Проверенные исходники rTorrent 0.9.8 и 0.16.21 и [локальный снимок совместимости](../../tests/php/RtorrentCompatibilityTest.php) содержат только `f.set_create_queued` и `f.set_resize_queued`. Несуществующие псевдонимы не следует вносить в политику.
4. Для P3 proxy17 замена `cat=$d.views=` на `d.views=` не доказана эквивалентной: daemon возвращает список, `cat` превращает его в строку, а [Ratio](../../plugins/ratio/init.js) ожидает строку. Отказ списка реален, но средство требует проверки формата результата.
5. Предлагаемое для P3 consumers9 разрешение редиректов по registrable domain или по одной только записи целевого хоста в rCookies небезопасно: у Snoopy банка кук плоская, без домена происхождения. Разрешённый переход передаст исходную сессию цели. Политика должна доказать право передать именно эту сессию.

## Дополнительные находки и поправки к самому документу

- **Новые пропуски в описании образа:** `PluginInitPathsTest.php` и `ImmortalSeedCategoriesTest.php` также требуют `tokenizer`. Это проверено запуском файлов в уже установленном образе с read-only bind mount и `--network none`; дополнение к nit portability37, а не новая продуктовая неисправность.
- **Неверная атрибуция второго раунда:** `credential-redirect-refused` уже присутствовал на стороне `old` в [delta.diff](check-recheck2-5eba5135-evidence/delta.diff). Пункт nit tests43 описывает реальную устаревшую формулировку, но неправильно датирует появление девятого сообщения.
- **Текст отклонённых пунктов повреждён:** не менее семи из десяти записей в разделе «Отклонённые находки» обрываются внутри слова или предложения (`акк`, `беспла`, `Безопаснос`, `SI` и др.). По документу нельзя восстановить ни полную гипотезу, ни основание отклонения; кодовые гипотезы проверялись отдельно. Это nit документации, не доказательство противоположного вердикта.
- **Контекст `/tmp` устарел:** на момент этой проверки `df -h /tmp` показывает tmpfs 4.5 GiB, а не 1.7 GiB. Объём зависит от загрузки машины; аргумент об ограниченном tmpfs остаётся верным, точное число из старого измерения применять нельзя.

- **Проверен синтаксический риск README Ygg:** дословно добавленный к копии существующего `conf/config.php` пример из `plugins/loginmgr/README.md` дал `PHP Parse error: unexpected token "<"` на втором `<?php`. Это не ошибка текущего рабочего `conf/config.php`, а инструкция, которая ломает его при буквальном исполнении.
